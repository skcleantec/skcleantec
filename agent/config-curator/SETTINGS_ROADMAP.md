# 화면 표시 설정 — 제품 로드맵 (ConfigCurator)

> **목표:** 접수·스케줄·팀 화면의 **색·배지·아이콘**을 업체(또는 사용자)가 **켜고 끄고**, 의미를 **한곳에서** 볼 수 있게 한다.

## 현재 (2026-09-01)

| 설정 종류 | 위치 | 한계 |
|-----------|------|------|
| 접수 축하 바 문구 | 관리자 → 사용자 등록 → **페이지 설정** | 브라우저 localStorage만 |
| 접수·스케줄 색/배지 | **코드에 고정** | 범례 일부만, 끄기 불가 |
| 도움말 `?` | 화면별 모달 | 분산, 표시 토글 없음 |

카탈로그: [`display-indicator-registry.json`](./display-indicator-registry.json)

## 제안 — 단일 허브

**메뉴:** 관리자 GNB → **설정** → **화면 표시** (`/admin/settings/display`)

### 탭 구성 (초안)

1. **접수 목록** — pin tier 색(범례 링크), 해피콜 강조 on/off, 보류 색(읽기 전용 안내)
2. **스케줄** — 슬롯 색(오전/오후/종일/사이/조율), 1건·종일·처리전 링, DB 배지
3. **팀 화면** — (팀장용) 손 일정 색, 해피콜 배지 등
4. **범례 미리보기** — 켜진 항목만 샘플 카드로 표시

### 저장 방식 (단계)

| 단계 | 방식 | 적합 |
|------|------|------|
| **1차** | `localStorage` `cbiseo.display.v1` | 빠른 출시, PC별 차이 OK |
| **2차** | `TenantDisplaySettings` (JSON) + API | 업체 전원 동일 규칙 |
| **3차** | 역할별 기본값 (마케터 vs 관리자) | PlatformOps 연동 |

## ConfigCurator 에이전트 역할

- 새 기능에 배지/색 추가 시 → registry 등록 + 이 로드맵에 설정 슬롯 제안
- 사용자 "색 너무 많아" → registry 기준 **끌 수 있는 것 / 범례만** 분류
- 구현 시 Maestro → ConfigCurator(설계) → DesignPulse(UI) → CodeGuardian(코드) → RoleQA

## 금지

- 표시 끄기로 **접수가 목록에서 사라지게** 하지 않음 (필터와 혼동)
- 정산·연계·취소 등 **법무/업무 필수** 배지를 "끄기"로 숨기지 않음 — `userConfigurable: false`
