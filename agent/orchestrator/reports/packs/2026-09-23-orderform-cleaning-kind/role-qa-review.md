## 버그

### P1 — 관리자 접수·스케줄에서 청소 종류가 안 보임

**재현 (정적)**  
1. 손님이 위저드에서 종류 확인 후 제출.  
2. 관리자가 서비스접수 또는 스케줄에서 그 접수를 연다.  
3. `InquiryEditCustomAnswersSection`은 **양식 커스텀 칸만** 그린다. `cleaningKind`는 시스템 JSON 키라 `intakeProfile.customFields`에 없다.  
4. 커스텀 칸이 0개면 「발주서 추가 정보」블록 자체가 안 나온다.

**기대**  
제출된 종류가 관리 상세에도 「청소 종류 · 입주청소」처럼 보인다.

**실제**  
- 보임: 발주서 목록 제출 스냅샷, 제출 메일, 팀장 상세, 리뷰 스텝.  
- 안 보임: 관리 스케줄/접수 수정(양면 상세), 접수 목록 칩.  
- CRM brief는 `templateAnswers` 배열이라, 양식 칸이 아니면 빠질 수 있음.

역할 「관리 = 제출분 확인」이 주 화면에서 깨진다.

### P2 — 클래식 폼 「확인」은 제출을 막지 않음

손님 본선은 위저드. 클래식(마케터 발급·폴백)은 「확인」이 성함으로 스크롤만 하고 `classicKindConfirmed`를 `handleSubmit`이 보지 않는다. 고르기만 하면 제출 가능.

### P2 — 목록 칩에 종류가 안 붙음

`resolveOrderFormListSnapshotForSubmit`은 `showInInquiryList` 양식 칸만 넣는다. `formatOrderFormListSnapshotValue`는 준비돼 있으나 키가 안 들어간다. 팀장 배정·스케줄 칩, 관리 목록 스냅샷에 기본 미노출.

### P2 — `?step=name` 등으로 welcome 확인을 건너뛸 수 있음

위저드가 이전 스텝 완료를 강제하지 않는다. 빈 값이면 제출은 서버가 막는다. 선입력·초안이 있으면 그림·확인을 안 보고도 진행된다.

### P2 — 에어컨 등 비입주 양식도 종류 필수

`POST /submit`이 모든 공개 제출에 `cleaningKind`를 요구한다. 사무실·에어컨 손님도 입주/이사/준공/거주/특수 중 하나를 고르게 된다.

## 통과한 핵심 계약

- 서버 허용 집합만 저장. 한글 라벨·임의 문자열은 400.  
- 선입력 overlay가 고객 변조를 덮음.  
- 접수 PATCH 커스텀 동기화는 양식 칸만 건드려 `cleaningKind`를 지우지 않음.  
- 미리보기 토큰 제출 400.  
- 안내사항 서명 게이트는 그대로 (`guide` 스텝).  
- Prisma 마이그레이션 없음.

## 확대 해석

- **CANCELLED / ON_HOLD / REVOKED:** 종류 필드와 무관. 스케줄 필터는 `Inquiry.status`만.  
- **빈 배정·해피콜 초과:** 영향 없음.  
- **배포 전 미제출 링크:** 종류 없음 → 손님이 고름. 기존 제출분 스냅샷에는 칸 없음 → 「—」.  
- **전화·수기 접수:** 제출 API를 안 타면 종류 없음. 정상.  
- **크로스 테넌트:** 새 mutate 없음. 토큰 + `assertPublicOrderFormAccess`.

## 수동 확인 (스테이징)

1. 손님: 고르지 않음 → 확인 비활성. 고름 → 그림 → 확인 → 성함.  
2. 제출 후 발주서 스냅샷·메일에 「입주청소」등.  
3. **관리 접수/스케줄 상세에 종류가 보이는지** (현재 코드상 실패 예상).  
4. 팀장 상세 「발주서 추가 정보」에 한글.  
5. 마케터 선입력 → 손님 라디오 잠금, DevTools로 다른 값 제출해도 선입력 유지.  
6. 미리보기: 확인으로 넘김, 제출 안 됨.

## PUSH-safe

**아니오.**

제출·JSON 저장·선입력 잠금·테넌트 가드는 스테이징에 올려도 데이터 사고 위험은 낮다. 다만 **관리자 주 화면에서 제출 종류를 못 보는 P1**이 있고, 그림 한글은 DesignPulse HIGH다.

푸시 전에: 관리(및 가능하면 CRM brief) 상세에 「청소 종류」한 줄. 그림 재생성은 병행 가능.

잔여만 남기고 올리면 손님 제출은 동작하지만, 역할 QA 기준으로는 관리 확인이 미완성이다.
