## 사용자 원문 요약
정리는 됐지만 가독성이 떨어지고, 업체의 충전·서비스 결제를 순발력 있게 바로바로 처리하는 부분이 약하다.

## 조사된 사실 (다시 조사 금지)
- `alimtalkChargeRequest.service.ts` `createAlimtalkChargeRequest` 는 PENDING 행만 만들고 **플랫폼 알림이 없다**. 승인은 업체 상세 부가서비스 탭에서만 가능(전 업체 대기 목록 없음).
- 이용료 입금 확인: 이메일 토큰(`tenantBilling.depositConfirm.*`) + 플랫폼 이용료 청구 화면.
- 이용료 카드결제: 플랫폼 쪽 결제창·수기 키인(`cardPayment.platform.routes.ts` `/usage-fee/*`, `usageFeeCardPayment.service.ts`). **업체가 스스로 카드 결제하는 화면은 없다.**
- 실시간 허브: `server/src/modules/realtime/` (WebSocket·알림) 존재.
- 화면 관찰(staging 1ff94b0): 업체 상세 「부가서비스」 탭이 패널 5개 + 긴 설명 문단의 세로 스크롤, 기능 표는 가운데 정렬 회색 글자, 하단 플랜 설명 문단 등 **설명문이 숫자·상태보다 크게 보인다**.

## Phase 1 — 돈 들어오는 일 즉시 처리 (최우선)

**에이전트:** CodeGuardian → DesignPulse → ConfigCurator → RoleQA · AppScout(결제 승인 대기열 UI 사례 2개, 3줄) 

1. **즉시 알림**: 아래 이벤트 발생 시 플랫폼 사용자에게 실시간 알림(기존 realtime 허브: 화면 토스트 + 알림음 + 사이드 배지) **+ 운영자 이메일 즉시 발송**(기존 플랫폼 SMTP).
   - 청소비서 지갑 충전 신청 · 이용료 입금 확인 요청 · 유료 전환 신청 · PG 가입 신청 · 바로빌 검토 대기
2. **오늘 할 일 = 돈 먼저**: 읽기 전용 집계 API `GET /api/platform/inbox` + 화면 재구성.
   - 맨 위 「돈 처리」 묶음: 충전 신청 / 입금 확인 요청 / 미납·연체. 각 줄에 **업체명 · 금액 · 입금자명(있으면) · 대기 시간 · [승인] [반려]** 를 **목록에서 바로** 처리(확인 모달 1번). 승인 로직은 기존 API 재사용.
   - 여러 건 체크 후 일괄 승인.
   - 대기 1시간 넘으면 주황, 24시간 넘으면 빨강.
   - 그 아래 「검토」 묶음: 가입승인 · 유료 전환 · 문의 링크 · PG 가입 · 바로빌.
3. 사이드 메뉴 「오늘 할 일」 총 대기 건수 배지(실시간 갱신).
4. 작은 수정: 업체 개요 설정 점검에서 Free 플랜은 「플랜·과금」 ✓ "무료 플랜 · 과금 없음".
관문: 다른 브라우저에서 충전 신청 → 플랫폼 화면에 5초 안에 토스트·배지 · 목록에서 승인 → 업체 지갑 잔액 즉시 반영 · 이중 승인 불가 · **사람 확인**

## Phase 2 — 가독성 정리 (플랫폼 전체)

**에이전트:** AppScout(SaaS 관리자 콘솔 2곳, 숫자·상태 우선 레이아웃) → DesignPulse → ConfigCurator → RoleQA

공통 규칙(플랫폼 화면 전체 적용, 공통 컴포넌트로):
- **숫자·상태가 먼저, 설명은 뒤로**: 패널 상단에 큰 숫자/상태 배지, 설명 문단은 ⓘ 툴팁 또는 접기.
- **상태 색 통일**: 정상 초록 · 확인 필요 주황 · 문제 빨강 · 해당 없음 회색 · 잠김 🔒. 같은 의미는 어디서나 같은 배지.
- **표**: 글자는 왼쪽 정렬, 금액은 오른쪽 정렬·천 단위, 행 높이 줄이기, 상태는 배지로.
- **업체 상세 「부가서비스」 탭**: 상단에 요약 줄(지갑 잔액 · 알림톡 · PG · 계산서 · 텔레CRM 상태 배지), 아래는 2열 카드(데스크톱). 플랜 설명 문단은 접기.
- **저장 버튼**: 탭 안 패널마다 흩어진 저장 버튼은 유지하되, 변경 사항이 있으면 하단 고정 바에 "저장 안 된 변경 N개" 표시.
관문: Free/Standard/SK클린텍 업체 상세 6탭 + 오늘 할 일 + 이용료 청구 스크린샷 전후 비교(리포트에 첨부) · 360px 모바일 · **사람 확인**
