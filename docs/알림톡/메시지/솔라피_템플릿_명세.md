## 공통 규칙 (모든 템플릿)

### 브랜딩·문의

| 항목 | 규칙 |
|------|------|
| **플랫폼명** | 고객 대면: **청소비서** (SK클린텍 노출 금지) |
| **`#{문의전화}`** | **테넌트 업체 전화** — 브랜드 `companyRegistration.phone` 우선, 없으면 테넌트 **업체등록정보** 전화 (`resolvePublicOrderFormCompanyTrust` 와 동일) |
| **`#{업체명}`** | 병합된 사업자 상호 |
| **플랫폼 고지** | 고객용 템플릿 본문 하단 3줄 고정 (아래 「공통 고지 문구」) |

### 공통 고지 문구 (고객용)

```
본 알림은 예약·접수 플랫폼 「청소비서」를 통해 발송되었습니다.
실제 청소 서비스 제공 및 문의는 #{업체명}(#{문의전화})으로 연락해 주세요.
청소비서는 예약 중개·접수 관리 플랫폼이며, 청소 시공의 당사자가 아닙니다.
```

### 버튼 URL — 방법 A (고정)

솔라피·카카오는 WL 링크에 **`https://` 프로토콜을 고정**하고, 경로·쿼리만 변수로 둔다.  
`#{발주링크}` 단독 입력은 **검증 오류** 난다.

| 용도 | 모바일·PC 링크 |
|------|----------------|
| 발주서 | `https://www.cbiseo.com/order/#{발주토큰}?tenant=#{업체코드}&brand=#{브랜드코드}` |
| 안내사항 | `https://www.cbiseo.com/info?tenant=#{업체코드}&brand=#{브랜드코드}` |

API 발송 시:

- `발주토큰` ← `order.token`
- `업체코드` ← JWT / 테넌트 `slug`
- `브랜드코드` ← `operatingCompany.slug` (없으면 빈 문자열 또는 쿼리 생략 처리)

기존 **링크 복사**는 `getOrderFormPublicUrl()` 로 **URL 한 줄** 생성 — 알림톡만 위 3변수로 분리한다.

### 대체 발송 (LMS)

- 운영 권장: **ON**, 유형 **LMS** (링크·주소 포함)
- 문자에는 **버튼 없음** → 발주 URL을 본문에 `https://www.cbiseo.com/order/...` 전체로 포함
- 변수명은 알림톡과 **동일**

### 솔라피 등록 상태 표기

| 상태 | 의미 |
|------|------|
| `draft` | 명세만 작성, 미등록 |
| `review` | 솔라피 검수 중 |
| `approved` | 카카오 승인, 템플릿 ID 확보 |
| `wired` | 청소비서 API 연동 완료 |

### 검수자 참고 의견 (공통 — 모든 템플릿)

솔라피·카카오 **템플릿 검수 요청** 시 「검수자 참고 의견」「템플릿 설명」란에 **각 템플릿 §의 복붙용 문단**을 넣는다. (본문과 별도 — 검수자가 **발송 상황·수신 동의·변수·URL**을 이해하도록)

**플랫폼 공통 설명 (필요 시 앞에 한 줄):**

> 「청소비서(cbiseo.com)」는 입주·이사 청소 업체가 쓰는 **예약·접수 SaaS**입니다. 알림톡은 **상담 중·예약 진행 중인 고객**에게만, **해당 업체가 발급한 발주·접수 건** 기준으로 발송합니다. 광고·프로모션 목적이 아닌 **예약 안내·접수 확인·일정 리마인드**입니다.

**각 템플릿 섹션 필수 항목:**

| 항목 | 내용 |
|------|------|
| **발송 상황** | 언제·누가·왜 받는지 (1~2문장) |
| **수신·동의** | 전화 상담·발주 링크 요청 등 **거래 관계 고객** |
| **변수** | `#{}` 가 **건당 실데이터**임 (샘플은 예시) |
| **URL·버튼** | `cbiseo.com` = 플랫폼 호스트, `tenant`/`brand` = **고객이 최초 예약·상담한 업체(브랜드)** — **정보공유·파트너 인계 후에도 송신(원) 테넌트·원 접수 브랜드** (§3.1) |
| **문의전화** | **청소 시공 업체** 번호 (플랫폼 CS 아님) |
| **플랫폼 고지** | 하단 3줄 — **중개·플랫폼** 고지 (카카오 필수) |

## 시스템 적용 아키텍처 (예정)

코드는 **`server/src/modules/alimtalk/`** 에 **독립 모듈**로 추가한다. (본 `docs/알림톡/메시지/` 폴더는 **명세·운영 문서** 전용.)

```
server/src/modules/alimtalk/
  alimtalk.types.ts          # 템플릿 코드·변수·트리거 enum
  alimtalkTemplateRegistry.ts # CBISEO_* → 솔라피 templateId, 변수 빌더
  alimtalkSolapi.client.ts   # Solapi API 래퍼
  alimtalkSend.service.ts    # triggerAlimtalk(tenantId, trigger, payload)
  alimtalk.routes.ts         # (선택) 수동 발송·로그 조회
```

| 레이어 | 역할 |
|--------|------|
| **명세 (본 문서)** | 솔라피 등록 본문·변수·버튼·LMS·트리거 정의 |
| **`alimtalkTemplateRegistry`** | 템플릿 코드별 변수 매핑 (DB inquiry → `#{접수번호}` 등) |
| **`triggerAlimtalk`** | 테넌트 ON/OFF · 잔액 · 발송 · 과금 로그 ([플랜](../솔라피_알림톡_도입_플랜.md) Phase 5) |
| **UI (후속)** | 발주 발급/제출 화면 「알림톡 발송」 버튼 → API |

환경변수 (예정): `SOLAPI_API_KEY`, `SOLAPI_API_SECRET`, `SOLAPI_KAKAO_PFID` 등 — `.env` / Railway Variables.

| 변수 | 설명 |
|------|------|
| `SOLAPI_API_KEY` / `SOLAPI_API_SECRET` | 솔라피 API 인증 |
| `SOLAPI_KAKAO_PFID` | 카카오 비즈니스 채널 pfId |
| `SOLAPI_FROM_NUMBER` | 발신번호 |
| `SOLAPI_ALIMTALK_TEMPLATE_ORDER_LINK` | `KA01TP260821085834166DanPJHVm7HA` (미설정 시 코드 기본값) |
| `SOLAPI_ALIMTALK_TEMPLATE_ORDER_DONE` | `KA01TP2608210907017889JVtrqGLFhq` |
| `SOLAPI_ALIMTALK_TEMPLATE_SCHEDULE_D2` | `KA01TP260821092336472avWT4PJf0Dn` |
| `ALIMTALK_CRON_SECRET` | D-2 배치 cron (미설정 시 `BILLING_CRON_SECRET` 폴백) |

## 제품·과금·운영 정책 (확정)

> **시스템 구현 시 최우선 참조.** 플랜 게이트·월 무료 건수·충전·과금·브랜드 변수·발송 방식·플랫폼 관리 UI는 아래와 **일치**해야 한다.

### 1) 플랜별 기능·월 무료 건수

| 플랜 (`Tenant.plan`) | 알림톡 기능 | **월 무료 발송** |
|----------------------|-------------|------------------|
| **Starter** (`starter` / Free 이하) | **사용 불가** (0건, UI·API 차단) | **0건** |
| **Standard** (`standard`) | 사용 가능 (**Standard 이상**) | **100건/월** |
| **Standard+** (`standard_plus`) | 사용 가능 | **150건/월** |
| **Premium** (`premium`) | 사용 가능 | **200건/월** |

- **기능 게이트**: `Tenant.plan` 이 **`standard` 이상**일 때만 알림톡 모듈·발송 허용. Starter(및 Free)는 **기능 자체 없음**.
- **모듈 라이선스**: `mod_alimtalk` — 플랫폼 **업체 상세 → 플랜 · 알림톡** 탭에서 ON/OFF (`defaultOn: false`, Standard tier).
- **월 무료 제공 토글**: `TenantAlimtalkWallet.monthlyFreeEnabled` — 플랫폼에서 OFF 시 **이번 달 무료 건수 미적용**(선불·유료만).
- **월 무료 건수 리셋**: **매월 1회**, **KST(Asia/Seoul) 달력 기준 1일 00:00**에 해당 테넌트의 `monthlyFreeUsed` 를 **0으로 리셋** (플랜별 `monthlyFreeQuota` 는 유지).
- **월 무료 건수**: **알림톡(ATA) 성공 = 1건**, **대체 LMS 성공 = 3건** 소진 (플랜 총량에서 차감). **유료 단가**는 채널별로 다름 (§2).

### 2) 유료 사용·충전 (무료 소진 후)

| 항목 | 규칙 |
|------|------|
| **알림톡(ATA) 단가** | **건당 20원** (최종 `type=ATA` · 무료 소진 후) |
| **대체 LMS 단가** | **건당 60원** (Solapi `replacement=true` · 최종 `type=LMS`) |
| **대체 SMS** | 본문 길이상 **LMS 위주** — SMS 발생 시 **채널별 단가** 별도 (추후 표) |
| **LMS 무료 건수** | 월 무료 잔여에서 **3건** 차감 (`monthlyFreeUsed += 3`). 잔여 **3건 미만**이면 무료 불가 → **유료 60원** |
| **ATA 무료 건수** | 월 무료 잔여에서 **1건** 차감 (`monthlyFreeUsed += 1`) |
| **충전 단위** | **50,000원** 단위만 |
| **1회 충전 상한** | **200,000원** (50k × 최대 4회 선택) |
| **지갑** | 테넌트 **`tenantId` 1개 = 충전 잔액 1개** (선불, 원화 정수) |
| **차감 순서** | ① 월 무료(ATA 1건 / LMS 3건 조건 충족 시) → ② 충전 잔액 **채널 단가**(ATA 20 / LMS 60) |
| **발송 전 잔액 검사** | 대체 발송 ON → **`monthlyFreeRemaining >= 3`** 또는 **`prepaidBalance >= 60`** (LMS 최악 가정). ATA만 허용 정책은 없음 |
| **잔액 부족** | 발송 **실패** + 로그 |

```
발송 가능 (개념):
  plan >= standard
  AND 템플릿 ON
  AND (monthlyFreeRemaining >= 3 OR prepaidBalance >= 60)

과금 확정 (Solapi 최종 수신 후 — §8):
  ATA + monthlyFreeRemaining >= 1 → FREE, monthlyFreeUsed += 1
  ATA + else → PAID, prepaidBalance -= 20
  LMS + monthlyFreeRemaining >= 3 → FREE, monthlyFreeUsed += 3
  LMS + else → PAID, prepaidBalance -= 60
```

### 3) 브랜드(OperatingCompany)와 테넌트 지갑

- **충전금·월 무료 건수**: **메인 테넌트(`tenantId`) 단위** — 산하 **모든 영업 브랜드가 공유**.
- **발송 시 브랜드 반영 (필수)** — 고객에게 보이는 값은 **고객 대면 브랜드 컨텍스트** 기준 (`resolveAlimtalkCustomerBrandContext` — §3.1):
  - `#{브랜드명}` ← `displayName` / `name`
  - `#{업체명}` ← `resolvePublicOrderFormCompanyTrust(..., operatingCompanyId)`
  - `#{문의전화}` ← 브랜드 `companyRegistration.phone` **우선**, 없으면 테넌트 업체등록 전화
  - `#{브랜드코드}` ← `operatingCompany.slug` (버튼 URL)
  - `#{업체코드}` ← **고객 대면 테넌트** `slug` (버튼 URL — §3.1)
- **잘못되면 안 되는 것**: 테넌트 기본명·기본 전화만 넣어 **다른 브랜드 건**을 보내는 것 → **registry에서 operatingCompanyId 필수**.  
  **정보공유·파트너 인계 건**에 **수신(미러) 테넌트·수신 측 기본 브랜드**를 넣는 것 → **금지** (§3.1).

#### 3.1) 정보공유·파트너 인계 — 고객 대면 브랜드 = **최초(송신) 테넌트**

> **확정 규칙.** DB **정보공유**(`mod_db_marketplace`)·**파트너 접수 연계**(`TenantInquiryShare`)로 **다른 업체(수신 테넌트·타업체)에 배정·인계된 접수**라도, 고객에게 가는 알림톡·LMS의 **브랜드명·업체명·문의전화·버튼 URL(`tenant`/`brand`)** 은 **항상 최초 고객 접점 테넌트(송신·원 접수)** 기준이어야 한다.

| 구분 | 알림톡 변수·URL | 과금·설정 |
|------|-----------------|-----------|
| **고객 대면** | **원(송신) 접수**의 `operatingCompanyId` + **원 `tenantId` slug** | — |
| **수신(미러) 접수** | 수신 테넌트 기본 브랜드·`getDefaultOperatingCompanyId` **사용 금지** | — |
| **월 무료·충전** | — | **원(송신) `tenantId` 지갑** (기존 §3와 동일) |
| **템플릿 ON/OFF** | — | **원(송신) 테넌트** 설정 따름 |

**해석 (고객 관점):**

- 고객은 **A업체(브랜드 X)** 에 예약·발주했고, 내부적으로 **B업체**가 시공·인수해도 알림톡에는 **「X」·X 문의전화·X 브랜드 URL** 이 나간다.
- 공통 고지 「실제 청소 서비스 제공 및 문의는 #{업체명}(#{문의전화})」도 **동일 — 원 브랜드** (플랫폼 CS 번호·수신 파트너명으로 바꾸지 않음).

**구현 (`server/src/modules/alimtalk/`):**

- `alimtalkCustomerContext.service.ts` — `resolveAlimtalkCustomerContextFromInquiry` / `FromOrderForm`
- `TenantInquiryShare` **target** 이면 `sourceInquiryId`·`sourceTenantId`로 치환 후 변수·과금
- `AlimtalkSendLog.customerFacingTenantId` / `customerFacingOperatingCompanyId` 기록
- D-2 배치·미러 `inquiryId`도 동일 resolver 경유 (**송신 테넌트 지갑·브랜드**)

**코드 참고 (연계·미러):**

- `server/src/modules/tenant-partners/tenantInquiryShare.service.ts` — `sourceInquiryId`, `sourceTenantId`, 미러 `targetOperatingCompanyId`
- `server/src/modules/db-marketplace/dbMarketplaceConfirm.service.ts` — 정보공유 인계 확정 → `createTenantInquiryShare`

### 4) 템플릿별 발송 방식 (확정)

| 코드 | 발송 | UI·트리거 |
|------|------|-----------|
| `CBISEO_CUST_ORDER_LINK` | **수동** | **마케터** 발주서 발급 완료 화면 **「알림톡 발송」** (고객 번호 확인 후 1건) |
| `CBISEO_CUST_ORDER_DONE` | **자동** | 고객 발주서 제출 성공 직후 (테넌트 설정 ON일 때) |
| `CBISEO_CUST_SCHEDULE_D2` | **자동** | 청소일 **2일 전** KST 배치 (테넌트 설정 ON일 때, 건당 1회) |

- **자동 2종**만 테넌트가 끄면 발송 안 함. **발주 링크**는 버튼을 눌러야만 발송.
- 플랫폼 관리자는 테넌트별로 **템플릿 ON/OFF** 를 따로 둘 수 있음 (아래 §5).

### 5) 플랫폼 관리자 — 「알림톡」 메뉴 (전용)

**경로**: 플랫폼 **업체 상세** (`/platform/tenants/:id`) → **플랜 · 알림톡** 탭 — **플랫폼 관리자 전용** (`PlatformUser`, 테넌트 업무 JWT와 분리).

| 기능 | 설명 |
|------|------|
| **테넌트별 현황** | 플랜, 이번 달 무료 **사용/잔여**, 충전 **잔액**, 최근 발송·실패 건수 |
| **충전금 관리** | 입금 확인 후 **충전 반영** (50k~200k 규칙), 충전·차감 이력 — `POST /api/platform/tenants/:id/alimtalk-policy/charge`, `AlimtalkWalletChargeLog` |
| **템플릿 선택** | 테넌트별 **보낼 템플릿만 ON** — OFF 템플릿은 수동·자동 모두 **미발송** |
| **(선택) 서식 ID** | 솔라피 `templateId` ↔ `CBISEO_*` 코드 매핑 (플랫폼 공통) |

### 6) DB·모듈 스키치 (구현 시)

### 8) 대체 발송(LMS)·Solapi 정산 — **테넌트 청구 가능**

**질문 요지**: 알림톡 실패 → 장문(LMS)으로 갔는지 Solapi에서 알 수 있는가? → **예. 테넌트에 채널별로 청구 가능.**

#### Solapi가 주는 정보 (공식 API)

발송 직후 응답만으로는 부족할 수 있음. **메시지 최종 상태** 조회·웹훅에서 확인:

| 필드 | 의미 |
|------|------|
| **`type`** | 최종 채널: `ATA` \| `LMS` \| `SMS` … |
| **`replacement`** | `true` = 알림톡(등) 실패 후 **대체 문자**로 전환됨 |
| **`replacements[]`** | 대체 발송 내역(수신번호·본문 등) |
| **`status` / `statusCode`** | `COMPLETE` + `4000` = 정상 처리 |
| **`balance.sum` / `balance.replacement`** | Solapi 계정 **실제 차감·환불·대체 추가금** |
| **`countForCharge`** | 그룹 단위 `ata` / `lms` / `sms` 건수 |
| **`price`** | 채널별 Solapi 단가 |

Solapi 정책: 대체 발송 시 **원래 알림톡 요금은 환불**되고, **LMS/SMS 요금이 별도 차감** ([대체발송 문서](https://solapi.com/developers/api/messages-disablesms)).

#### 청소비서 구현 (필수)

```
1. POST 발송 → solapiMessageId 저장, chargeStatus=PENDING
2. Webhook 또는 폴링으로 최종 상태 수신
3. type + replacement 로 deliveredChannel 확정
4. 테넌트 지갑 차감 (FREE 또는 PAID, 채널별 단가)
5. AlimtalkSendLog 갱신 — UI·플랫폼 「알림톡」에 「알림톡 / 대체문자」 구분 표시
```

- **`customFields`**: `{ tenantId, templateCode, inquiryId }` 를 Solapi에 넣어 웹훅·조회 시 **어느 테넌트 과금**인지 매핑.
- **선차감 금지**: 최종 채널 확정 후 차감 — **LMS 유료 60원**, **LMS 무료 시 used += 3**
- **플랫폼 손실 방지**: Solapi `balance.sum`과 테넌트 `tenantUnitPriceKrw`를 로그에 **둘 다** 남겨 마진 모니터링.

#### 테넌트 UI 표시 (예정)

| deliveredChannel | 고객 수신 | 무료 소진 | 테넌트 유료 차감 |
|------------------|-----------|-----------|------------------|
| `ATA` | 카카오 알림톡 | **1건** | **20원** |
| `LMS` | 장문 문자(대체) | **3건** | **60원** |
| 실패 | 없음 | 0 | 0원 |

## 3. `CBISEO_CUST_SCHEDULE_D2` — 예약 일정 확인(청소 2일 전)
