# 위약금 구조화 · 안내사항 치환코드 · 알림톡 D-2 — 2단계 플랜

> **목표**  
> 1) 브랜드별 위약 설정은 **숫자·유형만** 입력하고, **문장은 시스템 고정 템플릿**으로 생성  
> 2) 발주서 **안내사항(/info)** 은 주변 문구는 업체가 편집, **일자·위약 치환코드는 기본 삽입**  
> 3) 그다음 **알림톡 D-2** 를 `#{무위약마감일}` + 고정 본문 + [안내사항 확인] 으로 **재검수**

**선행 문서**

- [`메시지/솔라피_템플릿_명세.md`](./메시지/솔라피_템플릿_명세.md) — 현재 `CBISEO_CUST_SCHEDULE_D2` (고정 「오늘까지」·청소 2일 전 배치)
- `shared/operatingCompanyCancellationPolicy.ts` — 정책 모델·`renderTierLine` 고정 문장
- `shared/orderFormGuidePlaceholders.ts` — `/info`·발주 안내 치환
- `.cursor/rules/alimtalk-template-docs.mdc` — Phase 2 명세 갱신 의무

## 배경 · 왜 2단계인가

| 문제 | 설명 |
|------|------|
| 업체마다 **무위약 기준일**·**구간 %** 가 다름 | `OperatingCompany.config.cancellationPolicy` 로 이미 브랜드별 저장 |
| 알림톡은 **승인된 고정 서식 + `#{}` 변수** 만 가능 | `{{cancellationPolicy}}` 전문·업체 자유 문장은 **검수·길이·예측 불가** |
| 현재 D-2 알림톡 | **청소 2일 전 고정** + 본문 **「오늘까지」** — `freeChangeDaysBefore !== 2` 이면 **고객 안내와 불일치** |
| 안내사항 편집 | `{{cancellationPolicy}}` 를 **수동 복사**해야 함 — 누락·구버전 문구 위험 |

**원칙 (확정)**

- **웹 `/info`·발주 ACK** → 구조화 설정 → **치환코드로 전체 위약 문장** 노출 가능  
- **알림톡** → **마감일(또는 N일) 변수 1~2개 + 고정 문장 + 안내사항 버튼** — 상세 위약은 `/info`  
- 업체가 알림톡·카카오 본문을 **직접 편집하지 않음** (플랫폼 템플릿 소유)

## Phase 1 — 위약금 구조화 + 안내사항 치환코드 (먼저)

### 1-1. 정책 UI · 데이터 모델

**설정 항목 (브랜드 · 영업 브랜드 → 위약금)**

| 항목 | 입력 | 생성 문장 (고정 템플릿) |
|------|------|-------------------------|
| **무위약 기준일** | `freeChangeDaysBefore` (0~365, 일) | `{{freeChangeDaysLine}}` |
| **위약 구간** | `daysBefore` + `kind` + `percent`(해당 시) | 구간별 치환코드 1줄 (아래) |

**유형 (`kind`) — 유지**

- `percent` — 「{당일/전일/N일 전} … 위약금 {n}%」
- `no_cancel` — 「… 취소·변경 불가」
- `deposit_forfeit` — 「… 예약금 반환되지 않음」

**제거·축소 (Phase 1)**

- `custom` (직접 입력) — **UI에서 제거** (또는 레거시 읽기 전용 + 마이그레이션 안내)  
  → 알림톡·검수 예측 가능성을 위해 **자유 문장 입력 금지**
- `tier.note` (보조 설명) — **선택 유지 가능**하나, 치환코드·알림톡 변수에는 **넣지 않음** (미리보기·/info 전용 각주 정도만)

**고정 문장 소스 (단일)**

- `shared/operatingCompanyCancellationPolicy.ts` 의 `renderFreeChangeDaysBeforeLine` · `renderTierLine`  
- 서버 mirror: `server/src/lib/operatingCompanyCancellationPolicyCore.ts` 동기화 유지

### 1-2. 치환코드 체계 (신규·정리)

**기존 (유지)**

| 토큰 | 내용 |
|------|------|
| `{{cancellationPolicy}}` | 기준일 한 줄 + 모든 구간 줄 (줄바꿈) |
| `{{cancellationPolicyBullets}}` | 위와 동일을 `•` 목록 |
| `{{freeChangeDaysLine}}` | 「날짜 변경은 청소일 기준 N일 전까지…」 |

**신규 (Phase 1)**

| 토큰 | 내용 | 비고 |
|------|------|------|
| `{{freeChangeDaysBefore}}` | 숫자만 (예: `2`) | 문장 조합용 |
| `{{penaltyLine:0}}` | `daysBefore === 0` 구간 1줄 | 없으면 빈 문자열 |
| `{{penaltyLine:1}}` | `daysBefore === 1` 구간 1줄 | |
| `{{penaltyLine:2}}` | `daysBefore === 2` 구간 1줄 | |
| `{{penaltyLines}}` | 모든 구간 줄 (줄바꿈, 기준일 줄 **제외**) | |
| `{{freeChangeDeadlineDate}}` | **접수·발주 컨텍스트 있을 때** `preferredDate − freeChangeDaysBefore` 의 **YYYY-MM-DD** | 발주 ACK·일정 확정 후 |
| `{{freeChangeDeadlineLabel}}` | 「2026-08-25(월)」 등 표시용 | 서버/클라 공통 포맷터 |

> `penaltyLine:N` 은 **N = daysBefore** 키. 구간이 없으면 치환 결과는 빈 문자열(해당 줄 삭제 또는 공백 처리 규칙을 `expandGuidePlaceholders` 에 명시).

**구현 위치**

- `shared/orderFormGuidePlaceholders.ts` — 토큰 상수·`GuidePlaceholderContext` 확장·`expandGuidePlaceholders`
- `server/src/lib/orderFormGuidePlaceholders.ts` — mirror
- `ORDER_FORM_GUIDE_PLACEHOLDERS` 목록·설명 갱신 → `AdminOrderFormNoticePage` 치환코드 안내

### 1-3. 발주서 설정 · 안내사항 (편집 UX)

**파일:** `AdminOrderFormNoticePage.tsx`, `orderInfoDefaultSections.ts`, `guideDefaults.ts`

**기본값 (취소·변경 안내 섹션) — 제안**

```text
{{freeChangeDaysLine}}
{{penaltyLine:2}}
{{penaltyLine:1}}
{{penaltyLine:0}}
(업체 추가 문구는 아래에 자유 편집)
예약일 14일 이내 취소 시 예약금은 반환되지 않음을 양해 부탁드립니다.
```

- **`{{cancellationPolicy}}` 단일 블록** 대신 **구간별 코드**를 기본 삽입 → 업체가 **중간 줄만** 빼거나 순서 변경 가능  
- **`{{cancellationPolicy}}` 는 유지** — 한 번에 넣고 싶은 업체용

**편집 UX**

1. 치환코드 안내 패널에 **신규 토큰** + 「무위약·위약 기본 블록 삽입」버튼  
2. **신규 테넌트 / 「기본 문구로 초기화」** 시 위 구조로 시드  
3. **브랜드 위약금 탭** 미리보기에 **토큰별 생성 결과** 표 (이미 미리보기 있음 → 토큰별 탭 추가)

**발주서 청소날짜 ACK / 동의 문구**

- `orderFormServiceDateAckDefaults` 등 — `{{freeChangeDaysLine}}` **기본 포함** 여부 점검  
- 일정 확정 후에는 `{{freeChangeDeadlineDate}}` 사용 가능한 문구 템플릿 제공 (선택)

### 1-4. 마이그레이션

| 대상 | 처리 |
|------|------|
| `kind: custom` 구간 | 저장 시 경고 → `percent` 또는 `fallbackLine` 으로 수동 이전 안내, 또는 일회성 스크립트 |
| 기존 `infoContent` | 그대로 동작 (`{{cancellationPolicy}}` 유지) |
| `freeChangeDaysBefore` null | 기존과 동일 — 해당 줄 미표시 |

## Phase 2 — 알림톡 D-2 재검수 · 연동 (Phase 1 이후)

### 2-1. 템플릿 방향 (카카오 재검수)

**템플릿 코드:** `CBISEO_CUST_SCHEDULE_D2` **개정** (또는 `CBISEO_CUST_SCHEDULE_DEADLINE` 신규 후 전환)

**본문 골격 (고정 — 검수용)**

```
#{고객명}님, #{브랜드명} 입주·이사 청소 예약 일정을 안내드립니다.

■ 청소일: #{청소일} #{시간대}
■ 주소: #{주소}

취소·변경이 필요하시면 #{무위약마감일}까지 #{문의전화}로 말씀해 주세요.
#{무위약마감일}까지 연락 주시면 위약금 없이 처리해 드립니다.
이후 취소·변경 시에는 위약금이 발생할 수 있습니다.

자세한 취소·변경·위약금 기준은 아래 [안내사항 확인] 버튼을 눌러 확인해 주세요.

(공통 고지 3줄)
```

**변수 (신규·핵심)**

| 알림톡 변수 | 시스템 소스 |
|-------------|-------------|
| `#{무위약마감일}` | `preferredDate` − `freeChangeDaysBefore` (KST YYYY-MM-DD 또는 「8월 25일(월)」) |
| 기존 | `#{고객명}` `#{브랜드명}` `#{청소일}` `#{시간대}` `#{주소}` `#{문의전화}` `#{업체명}` 버튼용 slug·토큰 |

**넣지 않는 것**

- `{{cancellationPolicy}}` 전문  
- 구간별 % 문장 (→ `/info` + Phase 1 치환)

**검수자 참고 의견 (요지)**

- 발송일 = **무위약 마감일 당일 아침** (또는 마감일 = 발송일인 경우 「오늘」 설명)  
- `#{무위약마감일}` = **건당 실제 마감일**  
- 상세 위약 % → **안내사항 WL 버튼** (업체별 `/info?tenant&brand`)

### 2-2. 발송 로직 변경

**파일 (예상)**

- `server/src/modules/alimtalk/alimtalkScheduleD2.service.ts` — 후보 접수 조회 조건  
- `server/src/modules/alimtalk/alimtalkTemplateRegistry.ts` — `#{무위약마감일}` 빌드  
- `docs/알림톡/메시지/솔라피_템플릿_명세.md` — §3 전면 갱신  
- Railway `SOLAPI_ALIMTALK_TEMPLATE_SCHEDULE_D2` — 승인 ID 교체

**cron 조건 (변경)**

```
발송 대상일 = kstToday
접수 preferredDate = kstToday + freeChangeDaysBefore(브랜드)
```

- 브랜드별 `freeChangeDaysBefore` 가 다르면 **같은 청소일이라도 발송일이 다름** → 일 배치에서 `operatingCompanyId` 별 정책 로드  
- `freeChangeDaysBefore` null/0 → **발송 스킵** 또는 별도 정책 (운영 확정)

**과금·중복**

- 기존과 동일: `(tenantId, inquiryId, templateCode)` 1회  
- 템플릿 코드 유지 시 기존 발송 이력과 호환; 코드 변경 시 마이그레이션 정책 명시

## 의사결정 메모 (확정·가정)
