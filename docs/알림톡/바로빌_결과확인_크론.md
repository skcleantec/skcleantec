# 바로빌 알림톡 결과 확인 크론

바로빌로 접수한 알림톡은 바로 성공·실패가 확정되지 않습니다.  
1분마다 결과를 조회해 알림톡 성공, 문자 대체, 실패를 나눕니다.

기본 발송은 솔라피입니다. 서식의 보내는 곳이 바로빌일 때만 이 크론이 건을 집습니다.

## API

| 항목 | 값 |
|---|---|
| **경로** | `POST /api/admin/cron/alimtalk-barobill-result` |
| **주기** | 1분 (`* * * * *`) |
| **인증** | `Authorization: Bearer <secret>` 또는 `x-cron-secret` |
| **Secret** | `ALIMTALK_CRON_SECRET` → 없으면 `HAPPY_CALL_CRON_SECRET` → `BILLING_CRON_SECRET` |

일정 확인 알림톡 크론(`docs/ALIMTALK_SCHEDULE_D2_CRON.md`)과 같은 비밀값·같은 헤더를 씁니다. 그 크론은 15분마다라서, 결과 확인은 **따로** 1분 크론을 둡니다.

## Railway에 1분 크론 추가

1. Railway 프로젝트에서 **New Service → Empty** (또는 Cron) 로 서비스를 하나 만듭니다. 운영·스테이징 각각 만듭니다.
2. 서비스 설정 **Cron Schedule** 에 `* * * * *` 를 넣습니다.
3. 시작 명령은 아래입니다. `CRON_BASE_URL` 끝에 `/` 를 붙이지 않습니다. 운영은 `https://www.cbiseo.com`, 스테이징은 스테이징 공개 주소입니다.

```sh
curl -sf -X POST "${CRON_BASE_URL}/api/admin/cron/alimtalk-barobill-result" \
  -H "Authorization: Bearer ${ALIMTALK_CRON_SECRET:-$HAPPY_CALL_CRON_SECRET}"
```

4. 변수 `CRON_BASE_URL`, `ALIMTALK_CRON_SECRET`(또는 `HAPPY_CALL_CRON_SECRET`)을 그 서비스에 넣습니다. 비밀값은 이 문서에 적지 않습니다.
5. 배포 후 한 번 호출해 `checked` 가 숫자로 돌아오면 연결이 된 것입니다.

```sh
curl -sf -X POST "${CRON_BASE_URL}/api/admin/cron/alimtalk-barobill-result" \
  -H "Authorization: Bearer ${ALIMTALK_CRON_SECRET:-$HAPPY_CALL_CRON_SECRET}"
```

## 스테이징

스테이징은 허용된 시험 번호로만 발송합니다. 바로빌 서버는 코드에서 시험용으로 바꾸지 않고, 그 환경의 `BAROBILL_ENV` 값을 그대로 사용합니다.
