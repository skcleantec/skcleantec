# 일정 확인 알림톡 — 테넌트 발송 시점·18:00·발송 확인 플랜

> **목표**  
> 1) **테넌트 알림톡 설정**에서 「일정 확인(`CBISEO_CUST_SCHEDULE_D2`)」 **몇 일 전** 발송할지 지정  
> 2) **미설정 시** → **위약금 발생일 하루 전** · **KST 18:00** 자동 발송  
> 3) **발송 성공/실패**를 관리 화면에서 **간단히** 확인  

**선행 (staging 반영됨)**  
- `#{무위약마감일}` 변수 · 브랜드별 위약 정책 · cron 후보 조회 (`c7e4cdee`)  
- 솔라피 템플릿 **개정 검수**는 별도 ([`메시지/솔라피_템플릿_명세.md`](./메시지/솔라피_템플릿_명세.md) §3)

**관련 화면**  
- 테넌트 ADMIN: `/admin/team-leaders/alimtalk` → `AdminAlimtalkPage.tsx`  
- 플랫폼: `/platform/tenants/:id` → `PlatformTenantAlimtalkPanel.tsx` (충전·ON/OFF만 — **본 플랜 1차는 테넌트 ADMIN**)

## 1. 배경 · 현재와의 차이

| 항목 | **현재 (staging)** | **본 플랜 목표** |
|------|-------------------|------------------|
| 발송일 | `무위약 마감일 = 청소일 − freeChangeDaysBefore` **당일** | **위약금 발생일 − N일** (기본 N=1) |
| N 설정 | 없음 (브랜드 `freeChangeDaysBefore`에 묶임) | **테넌트** 알림톡 설정에서 지정 |
| 발송 시각 | cron 호출 시각에 의존 (문서상 09:00 가정) | **KST 18:00 고정** |
| 결과 확인 | `AlimtalkSendLog` DB만 | **알림톡 설정 화면**에 최근 발송 목록 |

### 「위약금 발생일」 정의 (단일 소스)

브랜드 `OperatingCompany.config.cancellationPolicy` 기준:

1. **위약 구간(`tiers`)이 1개 이상**  
   → **위약금 발생일** = `청소일(preferredDate) − max(tier.daysBefore)`  
   (가장 먼 구간부터 위약이 적용된다고 본다)

2. **구간 없고 `freeChangeDaysBefore > 0`만 있는 경우**  
   → **위약금 발생일** = `청소일 − (freeChangeDaysBefore − 1)`  
   (무위약 마감 다음 날부터 위약)

3. **둘 다 없음 / 0**  
   → 일정 확인 알림 **자동 발송 대상 아님** (스킵)

**예시 (청소일 8/27)**

| 브랜드 정책 | 위약금 발생일 | 기본 발송일 (N=1) | `#{무위약마감일}` (변수) |
|-------------|---------------|-------------------|-------------------------|
| 무위약 2일, 구간 1일前·당일 | 8/26 | **8/25** | 8/25 |
| 무위약 2일, 구간 **2일前**·1일前·당일 | **8/25** | **8/24** | 8/25 |
| 무위약 3일, 구간 1일前·당일 | 8/26 | 8/25 | 8/24 |

> 알림톡 **발송일**과 **`#{무위약마감일}`** 은 다를 수 있다.  
> 본문 변수는 **실제 무위약 마감일**을 그대로 넣고, **언제 보낼지**만 테넌트·기본 규칙으로 조정한다.

## 2. 테넌트 설정 (UI·저장)

### 2-1. 설정 항목

| 필드 | 저장 | UI (ADMIN 알림톡) | 기본값 |
|------|------|-------------------|--------|
| `scheduleD2Enabled` | 기존 `TenantAlimtalkTemplateSetting.isEnabled` | 「무위약 마감일 (자동)」 ON/OFF | ON |
| **`scheduleD2DaysBeforePenalty`** | **신규** (아래 스키마) | 「위약금 발생일 **며칠 전**에 발송」 숫자 입력 또는 선택 (0~14) | **`null` → 시스템 기본 1** |
| `scheduleD2SendHourKst` | **플랫폼 상수 18** (1차는 테넌트 변경 없음) | 도움말: 「매일 **오후 6시(KST)** 에 발송」 | **18** |

**UI 문구 (안)**

- 라벨: **일정 확인 알림 — 발송 시점**
- 입력: `[ 1 ] 일 전` (위약금 발생일 기준)
- 도움말:  
  「비우거나 1이면 **위약금이 적용되기 하루 전** 오후 6시에 발송합니다.  
  브랜드별 위약 구간이 다르면 같은 ‘1일 전’이라도 청소일까지 남은 일수는 달라질 수 있습니다.」
- 미리보기(선택): 기본 브랜드 정책으로 「청소일 8/27 → 발송 8/25」 예시 1줄

**0일** = 위약금 발생일 **당일** 18:00 (테넌트가 마감 당일 리마인드 원할 때)

### 2-2. DB · API

**스키마 (안)** — `tenant_alimtalk_template_settings` 확장 또는 JSON 컬럼:

```prisma
model TenantAlimtalkTemplateSetting {
  // ... 기존
  scheduleD2DaysBeforePenalty Int? @map("schedule_d2_days_before_penalty")
  // null = 기본 1
}
```

- **마이그레이션** 필수 (`prisma migrate` only)  
- `GET/PATCH /api/alimtalk/settings` — `scheduleD2DaysBeforePenalty` 포함  
- `patchPlatformTenantAlimtalkPolicy` — 1차는 **미포함**(테넌트 ADMIN만). 필요 시 2차에 플랫폼 override

### 2-3. 검증

- `scheduleD2DaysBeforePenalty`: `null` 또는 **0 ~ 14** 정수  
- SCHEDULE_D2 OFF면 offset 저장은 허용하되 발송만 스킵

## 3. 발송일·시각 계산 (서버)

### 3-1. 단일 헬퍼 (신규)

**파일:** `shared/alimtalkScheduleD2Timing.ts` (+ server mirror)

```text
computeFirstPenaltyStartYmd(preferredDateYmd, policy) → Ymd | null
computeScheduleD2SendYmd(preferredDateYmd, policy, tenantOffsetDays?) → Ymd | null
  tenantOffsetDays: null → 1 (기본)
  return subtractDays(firstPenaltyStartYmd, tenantOffsetDays)
```

기존 `alimtalkScheduleD2.helpers.ts`의 `resolveScheduleD2DeadlineForInquiry`를 위 헬퍼로 **교체·확장**:

- `deadlineYmd` (무위약 마감) — **변수 `#{무위약마감일}`** 용 유지  
- `sendYmd` — cron·trigger 가드용  
- `firstPenaltyStartYmd` — UI 미리보기·로그용

### 3-2. trigger / cron 가드

**발송 허용 조건 (AND)**

1. `kstTodayYmd === sendYmd` (테넌트 offset 반영)  
2. `kstNowHour >= 18` (또는 cron이 **18:00 KST 1회**만 호출)  
3. 해당 `(tenantId, inquiryId, CBISEO_CUST_SCHEDULE_D2)` **미발송**  
4. 템플릿 ON · 라이선스 · 잔액 · 솔라피 templateId  

**`triggerAlimtalkScheduleD2`**  
- 현재 「무위약 마감일이 오늘」 가드 → **`sendYmd === 오늘` + (수동 테스트 시 시각 가드 생략 옵션)** 로 변경

### 3-3. Cron 스케줄 (18:00 KST)

**방식 A (권장)** — Railway / GitHub Actions cron **1일 1회 18:00 KST**

```http
POST /api/admin/cron/alimtalk-schedule-d2
Authorization: Bearer ${ALIMTALK_CRON_SECRET}
```

**방식 B** — 해피콜과 동일 **15분 폴링** + 서버에서 `hour === 18 && minute < 15` 일 때만 SCHEDULE_D2 실행  
(다른 cron과 엔드포인트 공유 시)

**문서·`.env.example`**

- `ALIMTALK_CRON_SECRET`  
- 스테이징/운영 cron 표에 **「매일 18:00 KST」** 명시 (`docs/알림톡/메시지/솔라피_템플릿_명세.md` §3 연동 메모)

### 3-4. 브랜드 vs 테넌트 우선순위

| 데이터 | 귀속 |
|--------|------|
| 위약 정책 · `#{무위약마감일}` | **접수 브랜드** (기존 §3.1) |
| **며칠 전 발송** | **billing 테넌트** 알림톡 설정 |
| ON/OFF | billing 테넌트 |

정보공유(미러) 접수도 **송신 테넌트** offset 적용 (기존 billing tenant 규칙 유지).

## 4. 발송 결과 확인 (간단 UI)

### 4-1. API

**`GET /api/alimtalk/send-logs`**

| 쿼리 | 설명 |
|------|------|
| `templateCode` | 기본 `CBISEO_CUST_SCHEDULE_D2` |
| `limit` | 기본 30, max 100 |
| `offset` | 페이지네이션 |

**응답 `items[]` (간단 필드)**

| 필드 | 소스 |
|------|------|
| `id`, `createdAt` | `AlimtalkSendLog` |
| `templateCode` | |
| `inquiryId`, `inquiryNumber` | join Inquiry |
| `customerName`, `preferredDateYmd` | Inquiry |
| `toPhone` | 마스킹 (`010-****-5678`) |
| **`status`** | `success` / `failed` / `pending` — `chargeStatus` + `errorMessage` + `deliveredChannel` |
| `deliveredChannel` | `ATA` / `LMS` / null |
| `errorMessage` | 실패 시만 |

**중복 키:** 이미 `(tenantId, inquiryId, templateCode)` 로 1회 — 목록은 **시도마다**가 아니라 **성공·실패 로그** 그대로 (실패 후 재시도 정책은 **1차: 1회만**, 실패 시 수동 재발송은 2차)

### 4-2. UI (`AdminAlimtalkPage`)

**「최근 일정 확인 알림 발송」** 카드 (SCHEDULE_D2 ON일 때만)

| 접수번호 | SK2608250001 |

- `ListPaginationBar` 또는 최근 30건 고정 (1차는 **고정 30건**, 페이지 없음)  
- 5분·접속 시 `load()` — WebSocket 불필요

### 4-3. (선택 2차) 접수 상세 배지

- 접수 목록/상세에 「일정 알림톡 발송됨 8/25」 칩 — `AlimtalkSendLog` exists 쿼리

## 8. 금지 · 주의

- 발송일을 **`freeChangeDaysBefore`와 무조건 같게** 두지 않는다 (테넌트 offset·구간 max 반영)  
- **09:00 cron** 문서/운영과 **18:00** 혼재 금지 — cron 표 일원화  
- 플랫폼·테넌트 **두 곳에서 서로 다른 offset** (1차는 테넌트만)  
- 발송 실패 시 **무한 재시도 cron** (1차는 1접수 1로그 1회 유지)
