## 2. 글자 — 5단계

| 단계 | 클래스 | PC | 모바일 | 쓰는 곳 |
|---|---|---|---|---|
| 페이지 제목 | `text-fluid-xl font-extrabold` | 25 | 19 | 화면마다 하나 |

## 6. 부품

### 버튼 — `components/ui/Button.tsx` 하나만
- 종류 4: `primary`(진한) · `secondary`(흰) · `danger`(빨간 테두리) · `quiet`(글자만). 크기 3: `lg` `md` `sm`.
- 한 덩어리(화면 머리·카드·팝업)에 `primary`는 **하나**. 순서는 항상 [보조] [주] — 주 버튼이 오른쪽 끝.
- `danger`는 지우기·취소처럼 되돌리기 어려운 일에만, 누르면 `confirmDialog`로 한 번 더 묻기.
- 금지: 파랑·보라·초록 바탕 버튼, 두 줄로 꺾이는 버튼, `<button className="…">` 직접 작성(새 코드).

### 필터 줄 — `components/ui/FilterBar.tsx`
- 순서: ① 기간 `FilterSegment` → ② 기준 `FilterSelect` → ③ 자주 쓰는 필터 최대 4개 `FilterSelect` → ④ 나머지는 `more`(「필터 더보기」) → ⑤ 검색 `FilterSearch`(남는 폭 모두).
- 모든 칸 높이 36, 「이름 값 ▾」 모양. 기본값과 다르면 파란 바탕.
- 걸린 필터는 `ActiveFilters` 칩 줄로, ✕로 바로 해제.
- 고르면 바로 적용 — 「조회」 버튼 없음.
- 모바일(<lg): 기간·검색 + 「필터 · N」 버튼 → 아래 시트(FilterBar가 자동 처리).
- 금지: 필터 2~3줄, 라벨과 셀렉트가 따로 노는 모양, 필터 사이 설명 문구.

### 상태 칩·태그 — `components/ui/StatusChip.tsx`
- 상태는 `StatusChip tone=…` 5색: `gray` 시작 전·끝나서 의미 없음 / `blue` 진행 중 / `green` 끝남 / `amber` 사람이 확인해야 함 / `red` 문제.
- 부가 정보(예약금·특이사항·사진·유입)는 회색 `Tag` — O/X 칸 대신.

### 표
- 머리 40(`bg-slate-50 text-fluid-2xs text-slate-500`) · 줄 52. 한 칸 최대 두 줄(위 본문, 아래 캡션).
- 상태 칸은 칩만. 작업 칸은 오른쪽 정렬, 버튼 1개 + ⋯(`RowActions`).
- 금액은 오른쪽 정렬. 열은 8개 안쪽 — 넘치면 태그로 합친다.
- 위 상태 구분은 밑줄 탭 + 개수.

### 모바일 카드
- 네 줄 고정: ① 이름(강조) + 캡션 + 오른쪽 상태 칩 ② 일정·주소·평수(본문) ③ 태그 ④ [전화] [상세] [⋯] (높이 44, 진한 버튼은 그 카드의 가장 급한 일 하나만).

### 팝업 — 3종류만 (`components/ui/Toast.tsx`)
- **결과 알림** `toast.success / toast.error` — 끝난 일 알림. 가운데 카드, 아이콘, 버튼은 카드 폭.
- **확인창** `await confirmDialog({ title, body, confirmLabel, danger })` — 같은 모양, 실행 버튼만 빨강.
- **입력 창** 제목+✕ / 내용 / 오른쪽 아래 [취소][실행]. 모바일은 아래 시트, 버튼 가로 가득(`IssueModalFrame` 패턴).
- 금지: `window.alert/confirm`, 목록 줄 안에 길게 쓰는 실패 이유(→ 칩 + 팝업), 화면 위쪽 띠 알림.
