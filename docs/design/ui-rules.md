# 청소비서 디자인 규칙 v3

> 2026-11-11 개정 (v2: 2026-10-31). 개발자 결정: **화면 디자인은 Claude가 맡는다.** 코딩 에이전트는 시안을 그대로 옮기고, 스스로 모양을 만들어 내지 않는다.
> 기준 시안: Claude 디자인 캔버스 「영수증 시작 안내」 ⑤~⑨ (현금영수증 발행 폼·목록, 세금계산서 목록·발행).
> 검사: `cd client && npm run ui:audit` — 위반 개수가 기준값보다 늘면 실패. 화면을 고친 뒤 `node scripts/ui-audit.mjs --update`로 기준값을 낮춘다.

## 0. 일하는 순서 (가장 중요)

1. **화면 모양이 바뀌는 일은 시안부터.** Claude가 디자인 캔버스에 PC·모바일 시안을 그리고, 개발자가 확정한 뒤에 코드를 쓴다. 시안 없이 화면 모양을 새로 만들지 않는다.
2. **시안을 그대로 옮긴다.** 폭·간격·배치·문구·순서는 시안 숫자 그대로. 시안에 없는 장식(그라데이션, 큰 그림자, 이모지, 색 배경 버튼)을 더하지 않는다. 옮길 때는 아래 토큰으로 바꿔 쓴다(숫자 클래스 대신).
3. **버튼·글자를 키우지 않는다.** 크기를 키워 눈에 띄게 하는 대신 위치·문구·작은 표시(점·주황 안내)로 알린다.
4. 다 옮긴 뒤 PC(1440·1280)와 모바일(390)을 **시안과 나란히 놓고 비교**한 다음 올린다.

## 1. 느낌 — 세련되고 가볍게

- 바탕은 연한 회청색(`bg-canvas` #F1F4F9), 그 위에 흰 카드. **카드는 테두리 대신 그림자**(`shadow-card`)와 큰 모서리(`rounded-2xl`).
- 입력칸은 **테두리 없이 연한 바탕**(`bg-field` #F4F6FA), 포커스 때만 `ring-2 ring-slate-300`.
- 선택(탭·기간·과세/면세·용도 등 2~4개 중 하나)은 **세그먼트**: 회색 트랙(`bg-track` #EEF1F6) 안에서 고른 칸만 흰색으로 떠오름(`shadow-thumb`). `components/ui/SegmentedControl` 하나만 쓴다. 파란·남색 바탕으로 선택을 표시하지 않는다.
- 줄마다 긋는 구분선 대신 **간격**으로 나눈다. 구역이 바뀔 때만 얇은 선(`slate-100`) 하나.
- 회색 글자는 `slate-*`만. 라벨·캡션 `text-slate-500`, 본문 `text-slate-700`, 강조 `text-slate-900`.

## 2. 색 — 역할로만

| 이름 | 값 | 쓰는 곳 |
|---|---|---|
| 남색 | `slate-900` #0F172A | 위 메뉴·사이드바, 제목, **주 버튼** |
| 파랑 | `blue-600` | 선택된 메뉴·링크 — **버튼 바탕으로 쓰지 않음** |
| 바탕 | `canvas` #F1F4F9 | 화면 바탕 |
| 입력칸 | `field` #F4F6FA | 입력칸·검색칸·작은 select 바탕 |
| 트랙 | `track` #EEF1F6 | 세그먼트 바탕 |
| 강조 연한 바탕 | `#F0FDF4` | 방금 만든·고친 줄 3초 강조 |
| 주의 | 주황 `orange-700` 글자 + 아이콘 | 기본값과 다를 때 등 「한 번 더 보세요」 |

- 종류 표시는 **작은 점(6px)+글자** 또는 **연한 배지**: 과세 파랑(#EFF6FF/#1D4ED8) · 면세 초록(#ECFDF5/#047857) · 영세 보라(#F5F3FF/#6D28D9). 진한 색 바탕 버튼으로 종류를 나타내지 않는다.
- 상태 색은 §6 상태 칩 5가지만.

## 3. 글자 — 5단계 (그대로)

| 단계 | 클래스 | 쓰는 곳 |
|---|---|---|
| 페이지 제목 | `text-fluid-xl font-bold` | 화면마다 하나 |
| 소제목·큰 숫자 | `text-fluid-base font-bold` | 카드 제목, 합계 금액 |
| 강조 | `text-fluid-sm font-semibold` | 버튼, 고객 이름, 탭 |
| 본문 | `text-fluid-xs` | 표 칸, 입력칸, 라벨 |
| 캡션 | `text-fluid-2xs` | 보조 정보, 칩, 표 머리, 안내 |

- 금지: `text-[12px]` 같은 숫자 크기, `text-xs`·`text-sm` 혼용. 시안의 11·12px → 캡션, 13px → 본문, 14·15px → 강조, 16~18px → 소제목, 22px 이상 → 페이지 제목.

## 4. 모양·높이·간격

- 둥글기: `rounded-lg` 버튼·입력칸·세그먼트 · `rounded-xl` 작은 카드·도구줄·드롭다운 · `rounded-2xl` 큰 카드·팝업·하단 실행줄 · `rounded-full` 칩. 금지: `rounded` `rounded-md` `rounded-sm` `rounded-[Npx]`.
- 높이: 28 표 안·세그먼트 칸 · 36 PC 기본(버튼·입력칸·검색) · 44 모바일 누르는 버튼·팝업 버튼 · 46 하단 실행줄 주 버튼(PC).
- 간격(4의 배수): 화면 여백 PC 24·32 / 모바일 12 · 덩어리 사이 16 · 카드 안쪽 PC 20~26 / 모바일 12 · 폼 줄 사이 16 · 칸 사이 8.

## 5. 배치 — PC와 모바일은 따로 설계

- **PC(lg 이상)와 모바일은 다른 화면이다.** 모바일 폼을 PC에서 늘려 쓰지 않는다.
- **PC 폭은 고정**: 목록 화면 `max-w-[1120px]`, 작성·발행 화면 `w-[1040px]`(예: 폼 640 + 간격 24 + 미리보기 376). 넓은 화면에서 늘리지 않는다(왼쪽 정렬).
- **PC 폼**: 라벨 열 88px + 값 열의 2열 그리드. 입력칸 폭은 내용에 맞게 고정(휴대폰 180 · 사업자번호 180~220 · 품목 220 · 이메일 260~360). 짧은 칸은 **한 줄에 묶는다**(상호·성명 / 업태·종목 / 품목·거래일). PC에서 세그먼트·입력칸을 `w-full`로 늘리지 않는다.
- **모바일 폼**: 1열, 라벨은 위, 칸은 폭 가득, 실행 버튼은 화면 아래 고정.

## 6. 흐름·부품

### 목록 → 만들기 → 목록
- 목록이 첫 화면. 머리줄 오른쪽 끝에 주 버튼 「+ ○○ 발행/추가」 하나.
- 누르면 **작성 페이지**(별도 주소 `/new`). 왼쪽 위 ‹ 뒤로가기(작성 중이면 `confirmDialog`로 확인).
- 저장·발행하면 **목록으로 돌아가** 토스트 + 새 줄 연한 초록 3초 강조. 「발행하기/내역」 같은 탭으로 한 화면에 섞지 않는다.

### 머리줄 (한 줄)
- 제목 + 상태 문구(점 + 글자, 예: 「● 바로빌 연결 · 인증서 26.12.06까지」) + 보조 텍스트 버튼(충전·내역) + 톱니(설정) + 주 버튼. 상태줄·지갑줄을 따로 두 줄로 쌓지 않는다.

### 긴 작성 화면
- 위에 **한 줄 도구줄**(흰 `rounded-xl`): 불러오기·검색·종류 선택을 모은다.
- 아래 **하단 고정 실행줄**(`sticky bottom-4 rounded-2xl shadow-bar`): 요약(배지·대상·건수) · 비용 · 합계 · 주 버튼.
- PC 옆 **미리보기 카드**(376px, sticky): 짧은 폼은 오른쪽에 결과 미리보기 + 주 버튼.

### 기본값 안내
- 설정한 기본값과 같으면 옆에 회색 「기본값」, 다르면 주황 아이콘 + 「기본은 ○○예요」. 주 버튼 문구도 「○○로 발행」처럼 바뀐다.

### 버튼 — `components/ui/Button.tsx`
- 종류 4: `primary`(남색) · `secondary`(흰) · `danger` · `quiet`(글자만). 크기 3: `lg` `md` `sm`.
- 한 덩어리에 `primary`는 **하나**, 오른쪽 끝. 금지: 파랑·보라·초록 바탕 버튼, 두 줄로 꺾이는 버튼, 새 코드에서 `<button className=…>` 직접 작성(세그먼트·메뉴 항목 등 부품 안은 예외).

### 목록 필터 줄 (한 줄)
- 상태 새로고침(quiet) → 기간 `SegmentedControl` → 필요한 select(바탕 `field`, 최대 3개) → 검색칸(`field`, 240~280px) → 오른쪽 끝 건수·페이지당. 「조회」 버튼 없음. 모바일은 줄바꿈 허용.

### 표
- 표 전체를 흰 `rounded-2xl shadow-card` 카드 하나에(필터 줄 포함). 머리 `bg-slate-50 text-fluid-2xs text-slate-500`, 줄 사이 `border-[#F1F5F9]`, 행 hover `bg-slate-50`.
- 한 칸 최대 두 줄(위 본문 강조, 아래 캡션). 금액 오른쪽 정렬 `tabular-nums`. 작업 칸은 버튼 1개 + ⋯(`ReceiptRowMenu`/`RowActions`).

### 상태 칩·태그 — `components/ui/StatusChip.tsx`
- `tone`: `gray` 시작 전 / `blue` 진행 중 / `green` 끝남 / `amber` 확인 필요 / `red` 문제. 표 안에서는 점 + 글자로 가볍게 써도 된다.

### 팝업 — `components/ui/Toast.tsx`
- 결과 `toast.success/error`, 확인 `await confirmDialog(...)`, 입력은 모달(모바일 아래 시트). 금지: `window.alert/confirm`, 화면 위 띠 알림.

## 7. 바꿔 가는 순서

1. 새 화면·새 코드는 처음부터 v3.
2. 기존 화면은 **Claude 시안이 확정된 화면부터** v3로 바꾼다. 시안에서 열 구성·버튼 위치·흐름을 바꿨다면 그대로 따른다(v2의 「모양만 바꾸기」 제한은 시안이 확정된 화면에는 적용하지 않는다). 시안이 없으면 v2처럼 모양만 정리한다.
3. 지금까지 v3로 바뀐 화면: 현금영수증(목록·발행), 세금계산서(목록·발행).
